# Сервис учёта материалов для творчества 🎨

Знакомая ситуация: садишься рисовать, а любимая краска закончилась. Или покупаешь моток пряжи, а дома находишь ещё три таких же. Этот проект появился, чтобы с таким больше не сталкиваться.

Это небольшое консольное приложение, в котором удобно вести учёт всего, что хранится у вас для творчества: красок, кистей, пряжи, бисера, тканей и прочего. Программа помнит, что у вас есть, в каком количестве, кто и когда что-то брал или докупал, и вовремя подскажет, что пора пополнить запасы.

## Для кого это

- для художников и иллюстраторов с их красками, кистями, холстами и бумагой;
- для тех, кто шьёт, вяжет и плетёт: ткани, нитки, пряжа, бисер, фурнитура;
- для студентов творческих специальностей;
- для всех, у кого дома копятся запасы для хобби;
- для небольших мастерских, где материалами пользуются несколько человек.

## Что умеет программа

После запуска вы увидите меню. Все возможности разбиты на три группы.

**Материалы.** Можно посмотреть весь список, добавить новый материал (если такой уже есть, программа не создаст дубликат, а прибавит количество), найти материал по части названия, посмотреть всё из одной категории, увидеть, что заканчивается, отсортировать список и удалить материал, который больше не нужен.

**Операции.** Когда вы берёте что-то для работы или докупаете запас, это записывается как операция: кто, что, сколько и когда. Взять больше, чем есть, программа не даст. Если ошиблись, операцию можно отменить: количество вернётся, а сама запись останется в истории с пометкой «отменена».

**Пользователи.** Можно посмотреть, добавить и найти пользователей. Это удобно, если материалами пользуются несколько человек, например в мастерской или в семье.

Ещё есть общая статистика: сколько всего позиций, сколько единиц в каждой категории, сколько материалов заканчивается.

Если случайно ввести буквы вместо числа, неправильный email или оставить поле пустым, ничего страшного не произойдёт: программа объяснит, что не так, и продолжит работу.

## Как запустить

Понадобится Python версии 3.10 или новее.

```
python -m venv venv
venv\Scripts\activate          # на Windows
source venv/bin/activate       # на macOS и Linux
pip install -r requirements.txt
python main.py
```

Сама программа использует только стандартную библиотеку Python. Зависимости (pytest и flake8) нужны для тестов и проверки кода.

## Из чего состоит программа

Внутри приложение построено на трёх классах. Каждый отвечает за свою часть предметной области.

### Material — материал

Хранит всё о конкретном материале: `id`, `name` (название), `category` (категория), `count` (количество) и `added_at` (дата добавления).

Материал сам следит за своим количеством: `count` сделан свойством (`@property`), поэтому записать туда отрицательное число просто не получится. Ещё материал умеет:

- `change_by()` — изменить количество (пополнить или израсходовать);
- `can_change_by()` — заранее проверить, хватит ли материала;
- `is_low_stock()` и `check_low_stock()` — сказать, заканчивается ли он (порог общий для всех, это атрибут класса `MIN_STOCK = 3`);
- `validate()` — проверить данные перед созданием (`@staticmethod`);
- `from_data()` — создать материал из данных JSON (`@classmethod`);
- `__str__()` — красиво показать себя: `Акварель (Краски) - 5 шт.`

### User — пользователь

Хранит `id`, `name` и `email`. Умеет проверять email (`validate_email()`), создаваться из данных JSON (`from_data()`) и показывать себя в виде `Анна Смирнова <anna@example.com>`.

### Operation — операция с материалом

Это связующее звено: операция хранит не номера, а сами объекты материала и пользователя. Атрибуты: `id`, `material`, `user`, `amount` (минус — расход, плюс — пополнение), `created_at` и `is_cancelled`.

- `kind` — свойство, которое возвращает «Расход» или «Пополнение»;
- `cancel()` — отменить операцию и вернуть количество материала назад;
- `__str__()` — строка вида `#3 2026-09-27 Расход: Акварель -1 шт. (Анна Смирнова)`.

### Как объекты связаны между собой

```
User ──создаёт──▶ Operation ──изменяет──▶ Material
```

Благодаря тому, что операция хранит ссылки на объекты, из неё сразу можно узнать всё нужное: `operation.material.name`, `operation.user.email` и так далее.

Функции, которые работают сразу со всем списком (поиск, фильтр, сортировка, статистика), остались обычными функциями в модулях рядом с классами: это действия над коллекцией, а не поведение одного объекта.

## Где хранятся данные

Всё лежит в обычных JSON-файлах в папке `data/`, их можно открыть любым текстовым редактором:

- `materials.json` — материалы;
- `users.json` — пользователи;
- `operations.json` — история операций.

В файле операции хранятся не сами объекты, а их номера:

```json
{
    "id": 3,
    "material_id": 1,
    "user_id": 1,
    "amount": -1,
    "created_at": "2026-09-27",
    "is_cancelled": false
}
```

При запуске программа читает файлы и превращает записи в объекты, а для операций находит нужный материал и пользователя по номерам. При сохранении всё происходит в обратную сторону. Этим занимается модуль `storage.py`.

Если какого-то файла нет, программа начнёт с пустого списка. Если файл повреждён или операция ссылается на несуществующий материал, программа сообщит об этом, но не упадёт.

## Структура проекта

```
├── main.py              – запуск, меню и вывод на экран
├── models/
│   ├── __init__.py      – позволяет писать from models import Material
│   ├── materials.py     – класс Material и функции для списка материалов
│   ├── users.py         – класс User и функции для списка пользователей
│   └── operations.py    – класс Operation и функции для истории операций
├── storage.py           – превращение JSON в объекты и обратно
├── utils.py             – аккуратный ввод данных от пользователя
├── data/                – JSON-файлы с данными
├── tests/               – автоматические тесты
├── requirements.txt     – список зависимостей
└── setup.cfg            – настройки flake8 и pytest
```

## Для разработчиков

Запустить тесты:

```
pytest -v
```

Тесты проверяют создание объектов и их атрибуты, строковое представление, методы классов, поиск, фильтрацию и сортировку, правило «нельзя израсходовать больше, чем есть», отмену операций и сохранение с загрузкой, включая восстановление связей между объектами.

Проверить оформление кода:

```
flake8 .
```

Если flake8 ничего не вывел, значит всё в порядке.
